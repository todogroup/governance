# Contributing to OSPO for Agents WG

Thank you for your interest in contributing to the OSPO for Agents Working Group! We welcome contributions from everyone, regardless of experience level.

## How to Contribute

### 1. **Share Case Studies**

Have your organization implemented OSPO practices for AI agents? We'd love to hear about it!

#### What We're Looking For
- Real-world experiences managing AI agents within OSPOs
- Challenges faced and how they were overcome
- Governance decisions made and rationale
- Tools and processes that worked well
- Lessons learned and recommendations

#### How to Submit
1. Open an issue in the [TODO Group ospology repo](https://github.com/todogroup/ospology/issues) with the label `OSPO for Agents`
2. Or discuss in the #ospo-for-agents Slack channel
3. Use the [Case Study Template](./templates/case-study-template.md) for structured submission

### 2. **Document Patterns**

Have you identified repeatable patterns for agent governance?

#### Pattern Submission Process
1. Create a markdown file following [Pattern Template](./templates/pattern-template.md)
2. Include:
   - Pattern name and description
   - Problem it solves
   - Solution approach
   - Real-world examples
   - Pros and cons
   - Variations
3. Submit as a pull request or discussion

### 3. **Contribute to Guidance Documents**

Help write best practices and guidance on OSPO practices for agents.

#### Areas We Need Help
- **Compliance & Licensing**: How to evaluate agent licensing implications
- **Security**: Securing agents in enterprise environments
- **Risk Management**: Assessing and mitigating agent-related risks
- **Organizational Readiness**: Preparing teams for agent adoption
- **Governance Frameworks**: Decision models and policy templates

### 4. **Review & Provide Feedback**

Review draft materials and provide constructive feedback.

- Check #ospo-for-agents for documents in review
- Leave comments on GitHub pull requests
- Share in Slack discussions
- Attend working group meetings

### 5. **Organize & Curate Content**

Help organize materials, creating indices, summaries, or structured collections.

## Contribution Guidelines

### Code of Conduct
All contributors must follow the [TODO Group Code of Conduct](https://github.com/todogroup/governance/blob/master/CODE_OF_CONDUCT.md).

### Licensing
- Code contributions: Apache License 2.0
- Documentation/Content: Creative Commons Attribution 4.0 (CC-BY-4.0)
- All contributions must include Developer Certificate of Origin (DCO) sign-off

### Pull Request Process
1. Fork the relevant TODO repository
2. Create a branch with a descriptive name (e.g., `ospo-agents/case-study-acme-corp`)
3. Make your changes
4. Include a clear commit message with DCO sign-off: `git commit -s -m "Add case study: ACME Corp"`
5. Open a pull request with:
   - Clear description of changes
   - Reference to related issues/discussions
   - Any relevant links or context
6. Respond to review feedback
7. WG members will merge upon approval

### Writing Style

- **Clear & Accessible**: Write for OSPO practitioners, not just technical experts
- **Concrete Examples**: Use real-world examples and case studies
- **Actionable**: Focus on what readers can implement
- **Inclusive**: Acknowledge different organizational contexts and sizes
- **Evidence-Based**: Ground recommendations in experience and best practices

## Getting Help

- **Questions**: Post in #ospo-for-agents Slack channel
- **Technical Help**: Open an issue in `todogroup/governance` repo
- **Ideas**: Start a discussion in #ospo-for-agents or create a GitHub discussion
- **Working Group Meetings**: Join bi-weekly sync calls (details in Slack)

Contributors are recognized in:
- Document author attributions

- WG acknowledgments section
- TODO Group community updates
